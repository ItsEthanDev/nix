# Implement

Read the current target, approach, work state, and affected implementation. Select one unblocked slice, establish a focused baseline, make the change, and run a direct check. Record task completion only after its result is verified. Run a broader affected phase gate once after its slices pass and the complete relevant feature gate once before feature completion. Rerun a passing gate only when a later change invalidates its evidence. Inspect the complete diff and report commands, results, and limitations. Inspect delegated artifacts and direct evidence rather than accepting a delegate's summary. Invoke formal `development-review` only when the user explicitly requests it or an authoritative plan, task, or instruction schedules it at this boundary; one scheduled review authorizes one pass. Neither implementation, delegation, phase completion, nor a failed check alone authorizes formal review.

If implementation changes a premise, decide whether it is a technical adjustment, a changed target, or an operational value. A change may start in code, the plan, or tasks, but reconcile affected owners through `project-documentation`. Ask for direction before adopting an agent-proposed material target change; a user-directed change needs no second approval. Remove obsolete tasks, even checked ones, retain completed work that remains relevant, and add tasks for remaining gaps. At completion compare delivered behavior with the current target and report any unmet obligation rather than concealing it with a status change.
